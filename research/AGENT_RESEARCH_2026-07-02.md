## Summary
Direct inspection of the repo (via clone) shows the actual pipeline is TF-IDF + tabular metadata features feeding classical/gradient-boosted regressors (LASSO/Ridge/ElasticNet/RF/XGBoost/LightGBM in `model_results.py`), not a graph neural network — so this cycle's research targets the text-representation layer rather than the graph-architecture layer that prior cycles (36, 37) explored. Two 2024-2025 papers (GPT/embedding-based citation-impact prediction, and MIRAI) show that swapping or augmenting TF-IDF with dense sentence embeddings measurably improves impact-prediction correlation, and both are directly benchmarkable against this repo's existing `model_results.py` comparison harness. A GraphSAGE/GCN citation-network reference implementation and a multi-field impact-prediction benchmark (SciImpact) round out this cycle's findings as future-direction context.

## Engineering Insights
- This repo's `feature_engineering.py` already isolates TF-IDF construction into one method (`extract_text_features`, ~line 121) and persists the fitted vectorizer via pickle — the same pattern extends cleanly to a second, parallel embedding-feature method without disrupting the existing pipeline.
- `model_results.py` already runs a clean 6-model comparison (LASSO/Ridge/ElasticNet/RF/XGBoost/LightGBM) with train/test R², MAE, RMSE reported — the natural place to add an "embedding features vs. TF-IDF features vs. combined" ablation column rather than building a new eval harness from scratch.
- MIRAI and the GPT-embedding paper both use only title+abstract (no full text, no citation graph) and still get useful signal — this is a low-cost feature addition (one embedding model call per paper, cacheable) compared to standing up a citation-graph pipeline.
- Citation-count targets are heavy-tailed; prior cycles' recommendation to report MALE/RMSLE alongside MAE/RMSE still applies and would make any embedding-vs-TF-IDF comparison this cycle proposes directly comparable to MIRAI's published Spearman's ρ.
- Cache embeddings by `arxiv_id` (e.g., a `embeddings.parquet` keyed the same way `tfidf_vectorizer.pkl` is persisted now) so re-running `model_results.py --demo` or a real run doesn't re-embed unchanged papers.
