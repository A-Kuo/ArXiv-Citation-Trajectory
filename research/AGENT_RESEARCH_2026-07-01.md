## Summary
Citation trajectory prediction has moved from static graph-feature models toward temporal/dynamic graph neural networks that model publication influence as it evolves over time. The strongest recent work (CDCHGN, 2025) combines node centrality, dual clustering, and time-injected attention to beat prior SOTA on the APS benchmark, while a foundational temporal-knowledge-graph approach (CTPIR, 2022) remains the closest conceptual match to this repo's stated approach. Both point toward concrete, implementable upgrades for the temporal transformer component already planned for this repo.

## Engineering Insights
- Version every trained model and timestamp every prediction — critical for a citation-trajectory model since ground truth (actual citation counts) only becomes available months to years later, making retrospective evaluation the main quality signal.
- Treat the training pipeline, not a single model file, as the deliverable: automate ingest → feature build → train → validate → register so the model can be refreshed as new arXiv/APS data arrives, rather than shipping a frozen snapshot.
- Log predictions alongside eventual ground truth in a queryable store; for citation trajectories this means storing a paper_id → predicted_curve → actual_curve table that gets backfilled over time, enabling delayed-feedback monitoring.
- Cold-start handling matters more here than in most GNN tasks — CTPIR's approach of aggregating metadata features (venue, authors, abstract embedding) for brand-new papers with no citation history yet is a near-mandatory feature, not an edge case.
- Prefer reporting MALE/RMSLE (log-scale error metrics) over raw MAE/RMSE for citation-count targets, since citation counts are heavy-tailed — this matches what CDCHGN and related benchmarks report and makes results comparable to published baselines.

## Recommended Next Actions
1. Add a metadata-based cold-start path (venue, author h-index proxy, abstract embedding) alongside the citation-graph features, so new/uncited papers get a reasonable initial trajectory estimate instead of a null/zero prediction — directly modeled on CTPIR's approach (arXiv:2210.00450).
2. Add node centrality (e.g., degree/eigenvector centrality within the citation graph) and edge-type encoding as input features to the existing temporal transformer, and report MALE/RMSLE alongside current metrics to benchmark against CDCHGN's reported gains.
3. Build a small prediction-logging table (`paper_id, predicted_trajectory, actual_trajectory, predicted_at, evaluated_at`) so future cycles can compute delayed-feedback accuracy instead of only training-time validation metrics.
